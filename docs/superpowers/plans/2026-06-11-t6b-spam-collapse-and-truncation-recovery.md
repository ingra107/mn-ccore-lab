## Part B: Truncated Completion Recovery Attempt

### Background

The Phase-2 description migration flagged 112 entries with `AT 50-CHAR CAPTURE LIMIT (likely truncated)`.
These bodies end abruptly at exactly 50 characters. The question: do `raw_descriptions.json` or `spine.json`
(the migration-time source snapshots) contain the full text?

### Audit methodology

```python
# Load raw_descriptions.json (55 projects, pre-migration snapshot of projects.description)
# Load proposed.json (55 projects, with entries including truncated flag)
# For each truncated entry: find the project's raw description, locate the body text,
# check whether the raw source line extends beyond 50 chars
```

### Finding: truncation predates the snapshot

**All 112 truncated entries are also truncated in `raw_descriptions.json`.**

Example from `admin-tasks`:
```
raw source line: "[2026-03-13] ✓ Email Julia Heneghan re EHR data pipeline after Br"
entry body:       "Email Julia Heneghan re EHR data pipeline after Br"  (50 chars, identical)
```

The raw source `description` field itself ends at the same 50-char point. This means the truncation
occurred at task-capture time — when tasks were originally logged in the project description, they were
typed or captured truncated. The migration preserved the source verbatim (as flagged in the proposed.json
notes: "kept VERBATIM, never completed — verify").

No entry in `spine.json` provides the fuller text either — spine entries are derived from the same
`description` source.

### Result

**0 of 112 truncated completions are recoverable.** The full text was never stored anywhere in the
migration artifacts. The truncation is a data-origination issue, not a migration artifact.

Live `activity_entries` currently has 129 rows with `length(body) = 50` (17 more than the 112 flagged in
proposed.json — the additional 17 happen to be exactly 50 chars but are not truncated; the flagged entries
are a subset identified by the migration's parsing logic).

**Action: leave as-is.** No UPDATE performed. The bodies are the correct representation of the
source data.
