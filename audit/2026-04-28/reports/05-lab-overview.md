**Date**: 2026-04-28

### 1. Executive read

- **The Lab Overview page is doing too many jobs at once and has not honored Rule 57.** It is simultaneously a personal-day surface (Your Week, Quick Wins, MyItems, Pomodoro Focus Time, Email Drafts, Proactive Brief), a lab-wide weekly-planning surface (Project Health, Pipeline, Team Pulse, Activity Feed, Stats), an admin-grade meta surface (System Health, Lab Health Score, Status Line), and an editorial showcase (CLIF Mini, Topic Bubbles, Grant Timeline). 20 cards in `CARD_REGISTRY` (`Dashboard.tsx:80-101`), with 4 tabs filtering them, makes the page a register browser instead of a planning surface. Half the registry duplicates Today; the other half should be the actual focus.
- **The grid mechanics (RGL v1.5.3 + drag/resize/pin/per-user persistence + per-section reconcile) are a genuinely well-built piece of infrastructure** — the hover-only `⋮⋮` handle (`dashboard-grid.css:74-97`), SE resize indicator (`dashboard-grid.css:137-160`), Pin overlay (`Dashboard.tsx:305-325`), `reconcileLayouts()` logic that preserves user positions while adding new cards below (`dashboardLayout.ts:91-111`), the print-mode override, and reduced-motion handling are all production-quality. Almost no lab-management hub gets this right.
- **Three big content/correctness bugs undermine the page**: (1) `UpcomingCard` ships with **hardcoded fake deadlines** — "R01 ADHERE-LPV LOI due", "K23 progress report", "CCI-ARDS data freeze" — generated as relative-to-today via `daysFromNow(12)` (`UpcomingCard.tsx:17-53`); (2) `GrantTimelineCard` ships with **hardcoded fake grant timelines** including 5 entries with fixed years 2023-2032 (`GrantTimelineCard.tsx:7-13`) ignoring the `useGrants()` data it actually fetches in line 30; (3) `StatsCard` shows `totalCitations = 2626` as a **hardcoded constant** (`StatsCard.tsx:70`). Three "lab impressive" cards are lying to the team. This is the inverse of "ground truth" — and it's what visitors see on the marquee Overview page.

### 4. Top 5 high-leverage enhancements

**(1) Kill the lies, then re-decide the page.** The three hardcoded data sources (StatsCard citations, UpcomingCard deadlines, GrantTimelineCard timelines, ActivityFeedCard "CLIF expanding") undermine the team's trust in everything else on the page. **All in one PR**: delete the fake fixtures, wire to real APIs (or remove the cards). 4-6 hours of work, immediate credibility recovery. Without this fix, no other improvement matters because users reading the wrong R01 deadline learn to ignore the page.

**(2) Rule 57 enforcement — Lab Overview is lab-wide, Today is personal.** Move ProactiveBrief, QuickWins, MyItems, Pomodoro, EmailDraft, YourWeek to Today's surface (or remove if duplicative). Let Lab Overview be exactly: Project Health (default), Pipeline (default), Team Pulse (default — flip), Activity (default — wired to real activity_log), Stats (default), Grants Real (default — flip + wire), Insights (default — flip), Deadlines (real), File Activity (opt-in for ETL members). 8 cards instead of 20. The page becomes scannable in one screen.

**(3) Promote Lab Health from sidekick to centerpiece.** The `LabHealthScore` component is the most operationally honest piece of the page (real signals, capped deductions, surfaced reasons). Right now it sits in a 32-px-tall row next to a competing 4-chip StatusLine. Promote: make it a full hero card at the top, with the reason list expanded inline + drill-throughs to overdue / regulatory / stalled-mss / mentee-slipping pages. Drop StatusLine. Drop the editorial greeting. Open the page with a single 88px-tall card that says "Lab Health: 78 — 4 overdue tasks, 1 IRB renewal in 60d, 2 mentee milestones slipping" with click-throughs.

**(4) Honest role defaults + role-aware grid layouts.** ROLE_DEFAULTS are stale (`fellow: ['action-board', 'upcoming', 'stats']` — 3 cards). Refresh them post-Rule 57 cleanup: PI sees Lab Health hero + Project Health + Pipeline + Team Pulse + Insights + Grants + Activity. Fellow sees Lab Health (read-only) + their own progress card + their advisor's pipeline + recent activity. Coordinator sees Lab Health + ETL FileActivity + SystemHealth + Activity. The layout per role should be different, not just the card set.

**(5) Replace the IIFE-rendered chrome with a declarative DashboardHeader component.** Lines 339-449 are an IIFE returning JSX with ~110 lines of inline styles, three sub-components (StatusLine + LabHealthScore + tabs + customize button + adaptive indicator), and a 56px CLS-reserve. Extracting to `<DashboardHeader role={role} hasUpcomingMeeting={...} hasRegulatory={...} />` shrinks Dashboard.tsx by ~110 lines, makes the header testable in isolation, and lets you A/B header variants without touching the grid logic. This unlocks (3).

### 5. Today vs Overview boundary observations (Rule 57 honored?)

**No — Rule 57 has been violated, in both directions.** The CARD_REGISTRY currently includes `your-week` (Mon-Sun for the current user — pure Today material), `quick-wins` (user's tasks scored by urgency — pure Today material), `proactive-brief` (user's overdue/due-today + suggested focus task — *literally the Today page in card form*), `my-items` (user's action items), `email-drafts` (user's Gmail drafts), `pomodoro-stats` (user's focus time). Six personal cards on Lab Overview, three of them (`your-week`, `quick-wins`, `proactive-brief`) flagged `defaultVisible: true`, two of which (`weekly-progress`, `proactive-brief`) overlap explicitly with TodayPage's Right Now hero + completion timeline.

The reverse drift exists too — the StatusLine chip strip in the header (overdue / this week / IRB / done today, Dashboard.tsx:368) is Today material that escaped onto Overview because the page needs *some* operating-day signal to feel useful. That's a tell: **Lab Overview is masquerading as a second Today page because nobody pruned the personal cards when Phase 38 split the surfaces.**

The intended distinction (from CLAUDE.md Rule 57): Today = "what should I work on right now"; Lab Overview = "what's happening across the lab, weekly planning". Project Health, Pipeline, Team Pulse, Activity Feed, Stats, Grants, Insights are honest Lab Overview content — but they're crowded out by personal cards in the default visible set.

The `Dashboard.tsx:46-77` 4-tab IA (Overview / Projects / People / Deadlines) is a *hint* the team noticed the page doesn't have a coherent identity — splitting into tabs is a way to dodge the harder question of "what is this page actually for?" Rule 57 answers it; the implementation hasn't followed.

### 6. Brand & design-system observations

- **CategoryIcon (Rule 29) absent.** No card uses the lung/flask/heartbeat/cap category icons. Project Health rows render only a colored dot, not the project's category icon. Adding `<CategoryIcon category={project.category} />` to ProjectHealthRow would carry the brand into the most-used card.
- **HermesMark absent.** Insights, Brief, QuickWins are AI-generated suggestions. None carry the gold sparkle. Per Rule 29, "Hermes" cards should mark themselves as AI-derived. The ProactiveBrief card especially — it's literally a Hermes brief — uses a generic `Lightbulb` icon (`ProactiveBriefCard.tsx:1`).
- **Stage-fill tokens partial.** PipelineCard uses pinned hex + oklch (`#ffffff`, `#e8e0cc`, `#0f1923`, `oklch(0.16 0.005 250)`) instead of `--stage-fill-data-collection / writing / submitted`. ProjectHealthCard uses `STATUS_COLORS` mapping `Healthy→var(--green)`, `Critical→var(--maroon)` etc. — fine, but the heatmap cells use full `STATUS_COLORS[p.status] ?? var(--slate)` without theme adjustment for white text in dark.
- **`--gold-on-emphasis` opportunity.** ProactiveBrief due-today badge (`backgroundColor: var(--gold-emphasis), color: var(--gold)` — `ProactiveBriefCard.tsx:55-57`) is the exact pattern Rule 42 says needs `--gold-on-emphasis`. Light-mode contrast fail likely.
- **One accent per view violated.** The page uses teal (interactive), gold (emphasis + Hermes + grant labels), maroon (overdue + Critical), green (Healthy + done), orange (At Risk), pink-ish coral (Topic bubbles via `#db2777` `#dc2626`), blue (`#3b82f6` clif topic). The registry of cards as a whole has 8+ accent colors active. Per Rule 5 (one accent per view), this is too many — the page needs a discipline pass.
- **Inline hex everywhere.** TopicBubblesCard's `TOPIC_BUBBLE_COLORS` map (`#3b82f6`, `#dc2626`, `#9333ea`, `#d97706`, `#db2777`, `#0284c7`) and CLIFMiniCard's `#2d8a8a` and ActivityFeedCard's `#c9a84c` and PipelineCard's pinned hex chain all bypass the token system. Some of these are deliberate (CLIF teal pinned) but most are not.
- **Editorial copy on operational page.** "From bench to print" (Pipeline subtitle), "Lab updates" (ActivityFeed), "Multi-center ICU data" (CLIF Mini), "Multi-center ICU data infrastructure" detail strings — read like a marketing page. The design ethos pivot (2026-04-01) explicitly chose operational over editorial; these subtitles haven't been updated.
- **`framer-motion` `layoutId` on every BentoCard** (`BentoCard.tsx:45`) — `layoutId={`bento-${title.replace(...)}`}`. With 8+ visible cards, this is 8+ layout-shared elements being tracked. If any title collides (two cards share a title, unlikely here) layoutIds clash. Cheap to remove if the shared-layout animation isn't visually used.

### 7. Edge cases / failure modes

- **Empty lab (0 projects).** ProjectHealth shows a HeartPulse + "No project data available" — fine. Pipeline shows three bars at 12% min width (`Math.max((stage.count / maxCount) * 100, 12)` — `PipelineCard.tsx:57`) all with count=0 — visually misleading because the bars look populated. Stats shows 0/0/0/2626+. ActivityFeed shows 0 publications + the "CLIF expanding" hardcoded item — so the page never appears truly empty even when it should.
- **Lab with 71 projects + 647 tasks (current prod scale).** ActionBoardCard renders 647 rows in a `maxHeight: 300px` scroll. ProjectHealthCard renders all 71 in scroll within `maxHeight: 280-320px`. WeeklyProgress filters all 647 tasks for `completed_at.startsWith(dateStr)` 7 times (`WeeklyProgressCard.tsx:112-115`) on every render — and useMemo dep is `[tasks]` so it does re-run on every TanStack refetch.
- **Loading.** First paint shows skeletons in StatusLine, LabHealthScore, ProactiveBrief, Pomodoro, EmailDrafts, FileActivity, SystemHealth — but other cards (YourWeek, QuickWins, WeeklyProgress, ActionBoard) render with empty `tasks = []` defaults, so they show "0 due this week / 0 overdue / 0 done / 0 meetings" briefly before the data arrives. That looks worse than a skeleton.
- **Error.** No card has an error boundary. If `useTasks()` 500s, the whole grid renders empties. ProjectHealthCard's `useProjectHealth()` failing returns `data: undefined` → `summary = { total: 0, ... }` → "0 projects tracked" (false). All cards fail silent.
- **Logout / re-login as different user.** The 5 LS keys are not user-scoped; the per-section grid layout is via `userSlug || 'anon'` (`dashboardLayout.ts:23`). So `mnccore-dashboard-cards` (visible card set) is shared across users on the same browser. User A toggles off Pipeline; User B logs in on the same browser and is missing Pipeline. Privacy-low but correctness-broken.
- **CURRENT_DEFAULTS_VERSION = 4 reset.** When bumped, `mnccore-dashboard-cards` + `mnccore-dashboard-pinned` are removed (`Dashboard.tsx:147-149`). Per-section layouts (`mnccore-dashboard-layouts-v1:slug:section`) are NOT touched on version bump — so a user upgrading to a new version gets default card visibility but their *positions* are reconciled-not-reset, leaving cards in unexpected positions with the new visible set.
- **Mobile.** `DASHBOARD_GRID_BREAKPOINTS = { lg: 960, md: 720, sm: 480, xs: 0 }` measured against container width (Linear-correct). At 720-960 container width = 3 cols, ≤480 = 2 cols, ≤0 = 1 col. So a `span-2x2` Pipeline card on a tiny phone (<480) becomes 1 column tall. RGL drag/resize on touch is enabled by default but the SE handle is only opaque on `:hover` (`dashboard-grid.css:130-133`) — touch doesn't hover. Effectively, mobile users can't see the resize affordance to know it's resizable. Drag handle has the same hover-only opacity issue.
- **Reduced motion.** `prefers-reduced-motion` is honored in dashboard-grid.css line 174 (RGL transition off) and BentoCard via `useScrollReveal`, but the `status-pulse` animation on the live-dot (`Dashboard.tsx:362`), the `pulse-ring` in CLIFMini, the `overdue-pulse` in UpcomingCard, the IntersectionObserver-driven Pipeline + TopicBubble + CLIF entrance animations are NOT prefers-reduced-motion gated.
