Test Data Strategy

How should we populate the Hub so it looks like a real, active lab?

CONTEXT

Right now several pages look empty or have minimal data (Ideas: 0, Decisions: 1 test, Research Digest: few papers, Activity heatmaps: zeros for team members, Mentee Milestones: empty, IRB Tracking: empty). We want to populate realistic data so you can see what the Hub looks like when it's actually being used by a 15-person team.

All test data uses the test_delete_ prefix so it can be cleaned up in one sweep.

A

Realistic Simulation (Recommended)

Populate as if your actual team has been using the Hub for 3 months. Use real team member names as assignees, realistic project names with test_delete_ prefix, plausible meeting decisions, actual-sounding grant titles, believable mentee milestones.

  • Ideas: 8-12 ideas from different team members ("test_delete_Explore ML-based ventilator weaning prediction", "test_delete_Should we add ECMO data to CLIF?")
  • Decisions: 6-8 real-sounding decisions ("test_delete_Use propensity score matching for LTVV analysis", "test_delete_Target AJRCCM for gender disparities paper")
  • Mentee milestones: 4-5 per trainee (first presentation, manuscript draft, abstract submission, etc.)
  • IRB items: 3-4 regulatory items with realistic expiration dates
  • Activity: Seed activity_log entries so team member heatmaps show realistic patterns
  • Grants: 2 test grants with milestones ("test_delete_R01 Machine Learning ICU Outcomes")

Pros

  • See exactly what adoption looks like
  • Test every empty page at once
  • Screenshots will look real for demos

Cons

  • More data to clean up later
  • If cleanup fails, fake data sits alongside real
B

Test DB Only

Same realistic data, but ONLY in the test D1 database (mnccore-lab-test). Toggle with the X-Test-Mode: true header. Live site stays clean.

  • All the same data as Option A
  • Only visible when X-Test-Mode: true header is sent
  • Zero risk of fake data appearing on the real site
  • But: harder to casually browse and show people — need a browser extension or Playwright to see it

Pros

  • Zero risk to production data
  • Clean separation

Cons

  • Can't demo by just opening a browser
  • Need header injection to see it
C

Live + Cleanup Script

Same as A (realistic data in production D1) but we also build a one-command cleanup script that deletes everything with test_delete_ prefix across all tables.

  • All data in production — browse normally in any browser
  • Cleanup: npx wrangler d1 execute mnccore-lab --remote --file=cleanup-test-data.sql
  • Script handles FK constraints (deletes dependents first)
  • Run it once when you're ready to go live with real data

Pros

  • See it live, demo it live
  • One-command cleanup when ready
  • Best of both worlds

Cons

  • If you forget to clean up, team sees fake data on day 1
